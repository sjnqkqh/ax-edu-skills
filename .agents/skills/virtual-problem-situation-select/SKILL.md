# 가상 문제 선별

가상 문제 후보들 중 실습 대상으로 지정할 단 하나의 문제 상황을 선별하여, 후속 스킬(`virtual-problem-data-generate`)이 참조할 수 있는 표준 규격의 독립 마크다운 파일(`.md`)로 저장합니다.

## 핵심 원칙
- **원본 데이터 보존**: 이전 단계에서 생성된 문제 상황의 본문(배경 설명, 제약 사항, 비용, 입력 필드 등)을 임의로 변경하거나 왜곡하지 않고 원형 그대로 보존합니다.
- **해결책 미포함**: 선별 과정에서도 도구 추천, 해결 설계, 코드 등 해결 방안을 추가하지 않습니다.
- **단일 상황 집중**: 여러 후보가 주어지더라도 출력 파일에는 최종 선택된 1개의 문제 상황만 기록합니다.

## 입력
- **가상 문제 상황 후보 목록** (직전 스킬 산출물 또는 표준 규격 마크다운)
- **선택된 상황** (후보 번호 또는 상황 이름)
- **선정 사유** (선택 사항)

### 분기 처리 가이드
- **상황이 지정되지 않은 경우**: 후보 번호와 상황 이름 목록만 간결하게 보여준 후 사용자 입력을 대기합니다.
- **후보가 단 1개만 입력된 경우**: 해당 상황이 선택된 것으로 간주하여 즉시 파일 저장을 진행합니다.
- **선정 사유 입력 여부**:
  - 사용자가 입력한 사유가 있으면 이를 그대로 '선정 이유' 항목에 반영합니다.
  - 사용자가 사유를 적지 않은 경우, 추가로 묻지 않고 해당 상황의 「이 상황이 문제인 이유」 중 정성 문단을 선정 사유로 자동 채택합니다. (정량 비용 문장은 제외)

## 목표
선택된 상황 하나를 후속 스킬이 온전히 읽고 분석할 수 있는 단일 마크다운 파일로 파일 시스템에 저장합니다. (채팅창에만 출력하고 끝내지 않습니다.)

## 출력 파일 명세
- **파일명 형식**: 상황 이름을 하이픈(`-`)으로 연결한 마크다운 파일명  
  *(예: `운송사-청구서-운행-기록-맞추기.md`)*
- **문서 구조**:
  1. 헤더 블록 (직군, 직종, 업무 맥락)
  2. 상황 이름
  3. 선정 이유 (한 문단)
  4. 배경 설명
  5. 구체적 제약 사항
  6. 이 상황이 문제인 이유
  7. 비용 가정
  8. 기존 비용
  9. 이 상황을 다시 만들 때 필요한 입력

## 선정 이유 작성 규칙
선정 이유는 **해당 문제를 실습 과제로 선택한 배경과 의도**를 나타내는 한 문단으로 구성합니다.
- 사용자가 직접 작성한 사유가 있다면 수정 없이 반영합니다.
- 미작성 시 원본의 정성 설명 문단을 차용합니다. (근무일 20일 기준 N시간, NNN만 원 같은 정량 수치 문장은 제외)
- 해결 방법이나 특정 기술 스택(도구, AI 모델 등)은 기술하지 않으며, 새로운 허위 사실을 지어내지 않습니다.

## 자기 점검 (Checklist)
출력 및 파일 저장 전 다음 항목을 확인합니다.
- [ ] 선택된 단 1개의 상황만 파일에 포함되어 있는가?
- [ ] 원본의 배경 설명 문단 구분, 제약 사항 번호 목록, 비용 수치가 누락 없이 보존되었는가?
- [ ] 선정 이유가 1문단으로 정돈되어 있으며 정량 수치 문장이 배제되었는가?
- [ ] 해결책이나 정답 코드가 임의로 추가되지 않았는가?
- [ ] 파일이 올바른 경로와 파일명으로 저장되었는가?
