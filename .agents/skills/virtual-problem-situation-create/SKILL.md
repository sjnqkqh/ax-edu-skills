# 가상 문제 생성

실제 현장의 데이터를 확보하기 어려운 학습자를 위해, 특정 직군·직종에서 매일 일어날 법한 현실적인 가상 업무 문제 상황(병목 및 비효율 시나리오)을 생성합니다. 학습자가 해당 직무의 도메인 지식이 부족하더라도 업무 흐름과 병목 지점을 직관적으로 이해할 수 있도록 구체적인 장면을 묘사합니다.

## 핵심 원칙
- **문제 정의에만 집중**: 해결 설계, 자동화 코드, 도구 추천, 에이전트 구조 등 해결 방안은 일체 작성하지 않습니다. 문제 해결과 구현은 온전히 학습자의 과제입니다.
- **실무 표준 용어 사용**: 현업에서 실제로 통용되는 자연스러운 용어를 사용합니다. 일상이나 실무에서 쓰이지 않는 인위적인 축약어나 생소한 합성어를 임의로 만들지 않습니다.
- **사실 중심의 서술**: 연차나 시니어 커리어 같은 추상적 배경 설정은 배제하고, 사람이 어떤 문서를 열어 어떤 값을 대조하다가 막히는지 구체적인 작업 단위로 서술합니다.

## 입력
- **직군** (필수)
- **직종** (필수)
- **업무 맥락** (선택)

> 직군 또는 직종이 비어 있으면 해당 항목만 사용자에게 묻고 즉시 멈춥니다. 업무 맥락은 추가로 묻지 않으며, 직군·직종을 임의로 추측하여 생성하지 않습니다.
> 하루 처리 건수, 소요 시간, 인건비, 재작업률은 사용자에게 묻지 않고 에이전트가 실무 기준에 맞추어 합리적으로 가정합니다. 처리 인원수는 결과물에 명시하지 않습니다.

## 목표
직군·직종을 배경으로 가상 문제 상황 후보 3~5개를 생성합니다. 각 상황은 서로 다른 독립된 업무 문제입니다.

## 상황 조건
각 문제 상황은 아래 요건을 모두 충족해야 합니다.
1. **매일 반복되는 업무 장면**: 하루 단위로 지속 발생하는 정형화된 업무 루틴이어야 합니다.
2. **명확한 작업 흐름**: 무엇이 유입되고, 담당자가 어떤 화면/문서를 보며, 어디서 병목이 발생하고, 작업 실패 시 어떤 후속 작업이 발생하는지 드러나야 합니다.
3. **사람의 개입 구간**: 데이터 유입 후 사람이 직접 읽고, 분류하고, 기준 문서를 찾아보고, 초안을 작성하는 수작업 구간이 포함되어야 합니다.
4. **구체적 파일 형식 명시**: 배경 설명 및 제약 사항에 업무에서 열람하는 파일 형식(엑셀, PDF, JPG 등 실무 명칭)을 명시합니다.
5. **독립된 단일 문제**: 한 상황에는 하나의 핵심 문제만 집중적으로 다룹니다.

## 구체적 제약 사항
각 상황마다 8~12개의 번호 매겨진 문장으로 작성합니다.
- 한 문장에는 하나의 사실만 간결하게 기술합니다.
- 기술 순서: 유입 규모/시간 → 처리 대상 문서 → 병목/불일치 지점 → 작업 실패/재작업 결과.
- **필수 수치**: 하루 처리 건수, 1건당 소요 시간(분), 재작업 비율(%)을 반드시 문장에 명시합니다.
- 업무에 사용되는 파일 형식(엑셀, PDF, JPG 등)을 반드시 포함합니다.
- 담당자 인원수는 기재하지 않습니다.

## 비용 산정 기준
비용은 담당자 임금이 아닌 **회사가 부담하는 총 인건비** 관점에서 책정합니다.
- **시간당 회사부담 인건비**: **25,000원**으로 통일합니다. (직군 시세나 연차에 따른 가산 적용 금지)
- **월 기준**: 월 20 근무일로 환산합니다.
- **주의**: 수식 자체는 계산에만 활용하고 최종 결과물에는 계산 결과 수치만 표기합니다.

### 계산 공식 (내부 산출용)
- 일 처리 시간(시간) = 하루 건수 × 1건 처리 시간(분) ÷ 60
- 일 처리 인건비 = 일 처리 시간 × 25,000원
- 일 재작업 건수 = 하루 건수 × 재작업 비율
- 일 재작업 시간(시간) = 일 재작업 건수 × 1건 재작업 시간(분) ÷ 60
- 일 재작업 인건비 = 일 재작업 시간 × 25,000원
- 일 총발생비용 = 일 처리 인건비 + 일 재작업 인건비
- 월 총발생비용 = 일 총발생비용 × 20 (만 원 단위 반올림)
- 근무일 20일 소요 시간(시간) = (일 처리 시간 + 일 재작업 시간) × 20

## 출력 형식 및 순서
문서 서두에 **직군**, **직종**, (있으면) **업무 맥락**을 기재한 후, 각 문제 상황을 아래 순서와 구조에 따라 작성합니다.

```markdown
# 가상 문제 상황

- 직군: [직군]
- 직종: [직종]
- 업무 맥락: [맥락이 있는 경우 기재]

---

## 1. [상황 이름]

### 배경 설명
[2~3개의 문단으로 구성하며, 문단 사이에는 빈 줄을 넣습니다. 블릿 기호 없이 서술형 문장으로 작성합니다.
누가, 어떤 파일 형식의 문서를 받아 어떤 작업을 수행하는지 흐름을 보여줍니다.]

### 구체적 제약 사항
1. [하루 유입 건수 명시]
2. [1건당 처리 소요 시간(분) 명시]
3. [열람하는 파일 형식과 데이터 항목 기술]
... (총 8~12개 문장, 번호 목록 형태)

### 이 상황이 문제인 이유
[정성 문단]: 담당자가 매일 무엇을 확인하고, 어떤 파일과 대조하느라 시간이 소모되는지 현장 실무자의 표현으로 기술합니다.

[정량 문단]: 아래 표준 서식을 준수합니다.
이 업무는 근무일 20일 기준 N시간이 소요되며, 이를 월 단위로 환산하면 NNN만 원의 비용이 발생한다.

### 비용 가정
- 하루 건수: NN건
- 1건 처리 시간: NN분
- 시간당 회사부담 인건비: 25,000원
- 재작업 비율: NN%
- 1건 재작업 시간: NN분

### 기존 비용
- 시간당 회사부담 인건비: 25,000원
- 일 처리 인건비: NNN,NNN원
- 일 재작업 인건비: NN,NNN원
- 일 총발생비용: NNN,NNN원
- 월 총발생비용: N,NNN,NNN원

### 이 상황을 다시 만들 때 필요한 입력
- [필드명]: [데이터 타입 (문자열, 날짜, 원, PDF, 엑셀 등)]
... (합성 데이터 생성에 필요한 입력 필드 목록)
```

## 자기 점검 (Checklist)
출력 전 다음 항목을 확인합니다.
- [ ] 문제 상황 후보가 3~5개인가?
- [ ] 해결책, 자동화 방안, 에이전트 구조 등 답안이 포함되지 않았는가?
- [ ] 부자연스러운 인위적 축약어나 신조어가 없는가?
- [ ] 배경 설명에 엑셀, PDF, JPG 등 실무 파일 형식이 명시되었는가?
- [ ] 구체적 제약 사항이 8~12문장이며 하루 건수, 처리 시간, 재작업률이 포함되었는가?
- [ ] 시간당 회사부담 인건비가 25,000원으로 통일 계산되었는가?
- [ ] 정량 문단이 "이 업무는 근무일 20일 기준 N시간이 소요되며, 이를 월 단위로 환산하면 NNN만 원의 비용이 발생한다." 형식을 준수하는가?
- [ ] 산출물에 계산 수식이 노출되지 않고 결과 수치만 표기되었는가?
- [ ] 합성 데이터 생성을 위한 '필요한 입력' 필드 목록이 빠짐없이 포함되었는가?
