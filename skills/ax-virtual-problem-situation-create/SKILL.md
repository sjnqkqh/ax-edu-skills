# 가상 문제 생성

교육·포트폴리오용으로, 현장에 공개되지 않는 AX 효율화 문제를 가상 장면으로 만들어 준다. 이 스킬을 쓰는 학생은 해당 직무 전문가가 아닌 경우가 많다. 직군·직종을 배경으로, 현실에서 매일 일어날 법한 장면을 가정해 만들어 주는 것이 목적이다. 해결 설계, 자동화 방안, 에이전트 구조는 절대 쓰지 않는다.

## 문장
짧게 쓰는 것보다 있는 말을 쓰는 것이 우선이다.
없는 합성어, 줄임 제목, 새 분류 이름을 만들지 마라.
일상이나 현장에서 쓰지 않는 줄임말을 만들어 넣지 마라. 코딩에서든 실제 업무 현장에서든 불필요한 줄임말은 해악이다.

나쁜 예: 기술 산출물 껍질
좋은 예: 구체적 기술 설계 문서

제목도 있는 말로만 쓴다.

## 입력
- 직군 (필수)
- 직종 (필수)
- 업무 맥락 (선택)

직군 또는 직종이 비어 있으면 그 두 가지만 묻고 즉시 멈춘다. 업무 맥락은 물어보지 않는다. 직군·직종을 추측해서 채우지 않는다.

하루 건수, 처리 시간, 인건비, 재작업은 사용자에게 묻지 않는다. 에이전트가 가정한다. 처리 인원은 받지 않고, 결과물에도 적지 않는다. 비용은 총 소요 시간 × 시간당 회사부담 인건비로만 계산한다.

## 목표
가상 문제 상황 3~5개를 만든다. 각 상황은 서로 다른 문제 하나다. 직군·직종을 배경으로 가상 장면을 만든다.

## 상황 조건
각 상황은 아래를 모두 만족해야 한다.
1. 매일 반복되는 한 장면이다.
2. 무엇이 몇 개 들어오는지, 사람은 무엇을 보는지, 어디서 막히는지, 틀리면 무엇이 다시 생기는지가 나온다.
3. 한 상황에 문제 하나만 둔다.
4. AX로 효율화가 가능해야 한다. 같은 형태 입력이 반복되고, 사람이 읽고 나누고 찾아보고 초안을 쓰는 구간이 있어야 한다.
5. 답을 넣지 않는다. 해결 설계를 쓰지 않는다.
6. 연차·시니어 커리어 설정은 쓰지 않는다. 그 직무를 처음 보는 사람도 장면만 읽고 일이 보이게 쓴다.
7. 배경 설명과 구체적 제약 사항에 입력물의 파일 형식(엑셀, PDF, JPG 등)을 명시한다. 파일 형식은 현장에서 부르는 이름을 쓴다.

## 구체적 제약 사항
- 8~12문장.
- 한 문장에 사실 하나.
- 각 문장은 새 줄, 앞에 번호를 붙인다. 한 덩어리 문단으로 붙이지 않는다.
- 숫자, 대상, 막히는 지점, 실패 결과 순으로 쓴다.
- 하루 건수와 1건 처리 시간(분)은 반드시 문장 안에 넣는다. 재작업 비율이 있으면 그것도 문장 안에 넣는다.
- 사람이 여는 파일이 있으면 엑셀인지, PDF인지, JPG인지를 문장에 넣는다.
- 같은 사실을 두 문장에서 반복하지 않는다.
- 답을 넣지 않는다.
- 담당자가 몇 명인지는 적지 않는다.

## 비용
회사 입장에서 책정한다. 시간당 인건비는 지급 임금이 아니라 회사 부담 인건비다.

시간당 회사부담 인건비는 25,000원으로 가정한다. 직군 시세를 조사하거나 연차를 붙이지 않는다.

비용과 시간은 에이전트가 가정한다. 처리 인원은 변수에서 뺀다. 한 사람이 하루 종일 이 일만 하는 설정은 만들지 않는다. 하루 소요 분은 이 일에 드는 총 노동 시간이다. 월은 근무일 20일로 환산한다.

### 계산용 가정 (상황마다 에이전트가 정한다)
- 하루 건수
- 1건 처리 시간(분)
- 시간당 회사부담 인건비 (기본 25,000원)
- 재작업 비율
- 1건 재작업 시간(분)

### 계산 (내부용)
수식은 계산에만 쓴다. 결과물에 수식을 적지 않는다. 같은 수식을 상황마다 다시 쓰지 않는다.

- 일 처리 시간(시간) = 하루 건수 × 1건 처리 시간(분) ÷ 60
- 일 처리 인건비 = 일 처리 시간 × 시간당 회사부담 인건비
- 일 재작업 건수 = 하루 건수 × 재작업 비율
- 일 재작업 시간(시간) = 일 재작업 건수 × 1건 재작업 시간(분) ÷ 60
- 일 재작업 인건비 = 일 재작업 시간 × 시간당 회사부담 인건비
- 일 총발생비용 = 일 처리 인건비 + 일 재작업 인건비
- 월 총발생비용 = 일 총발생비용 × 20
- 근무일 20일 소요 시간(시간) = (일 처리 시간 + 일 재작업 시간) × 20

금액은 원 단위로 계산한다. AX 전환이 필요한 이유의 월 비용은 만 원 단위로 적는다.

### 기존 비용에 넣을 항목
- 시간당 회사부담 인건비
- 일 처리 인건비
- 일 재작업 인건비
- 일 총발생비용
- 월 총발생비용

숫자는 적되, 구체적 제약 사항에 나온 건수·시간을 문장으로 다시 풀지 않는다. 처리 인원은 적지 않는다.

## 출력 순서
맨 앞에 직군, 직종, (있으면) 업무 맥락을 한 블록으로 적는다. 그다음 상황마다 아래 제목과 순서만 따른다.

1. 상황 이름
2. 배경 설명
3. 구체적 제약 사항
4. AX 전환이 필요한 이유
5. 비용 가정
6. 기존 비용
7. 이 상황을 다시 만들 때 필요한 입력

### 배경 설명
블릿을 쓰지 않는다. 문장 여러 개를 2~3개 문단으로 나눈다. 마크다운에서 문단과 문단 사이에 빈 줄을 반드시 넣는다. 한 문단 안에서는 문장을 이어 쓴다. 문단 사이에 빈 줄이 없으면 렌더링에서 한 덩어리가 되므로, 빈 줄 없는 연속 줄바꿈만으로 끝내지 않는다.

누가, 어디서, 무엇이 어떤 파일 형식으로 들어오고, 그 앞에 어떤 일을 하는지 보이게 한다. 구체적 제약 사항에 넣을 숫자·막힘·실패는 여기서 미리 쓰지 않는다. 몇 명이 하는지는 쓰지 않는다.

### AX 전환이 필요한 이유
왜 전환이 필요한지를 적는다. 정성 한 문단, 빈 줄, 정량 한 문단. 합쳐 두 문단이다.

정성: 담당자가 매일 무엇을 읽고, 무엇을 확인한 뒤, 어떤 형식의 파일에서 찾아 맞는지 보는 일이 반복되는지를 이 장면 말로 쓴다. 문장은 현장에서 말할 법한 한국어로 쓴다.

정량: 아래 호흡을 따른다. 하루 횟수와 하루 분만 나열하지 않는다.

이 업무는 근무일 20일 기준 N시간이 소요되며, 이를 월 단위로 환산하면 NNN만 원의 비용이 발생한다.

N은 (일 처리 시간 + 일 재작업 시간) × 20 이다. NNN은 월 총발생비용을 만 원으로 반올림한 값이다. 정량 문단은 "이 업무는 근무일 20일"로 시작한다. 정성 문단과 정량 문단 사이에 빈 줄을 넣는다.

해결 방법, 도구, 에이전트, 인원 수는 쓰지 않는다.

## 작성 규칙
- 결과물은 한국어. 자연스러운 현장 문장으로 쓴다.
- 수식은 계산에만 쓰고 결과물에 반복하지 않는다.
- 해결 설계, 도구 추천, 에이전트 구조, 프롬프트 초안은 쓰지 않는다.
- "이 상황을 다시 만들 때 필요한 입력"은 합성 데이터를 만들 필드 목록이다. 입력 이름, 값의 형태, 파일 형식만 적는다. 빼지 않는다. 필드 이름도 있는 말로 쓴다.

## 자기 점검
내기 전에 확인한다.
- 상황이 3~5개인가.
- 없는 합성어, 줄임 제목, 새 분류 이름이 없는가.
- 배경 설명이 빈 줄로 나뉜 2~3문단인가.
- AX 전환이 필요한 이유의 정량 문장이 근무일 20일 기준 N시간, 월 NNN만 원인가. 하루 분만 적혀 있지 않은가.
- 정성 문단과 정량 문단 사이에 빈 줄이 있는가.
- 배경 설명과 구체적 제약 사항에 엑셀, PDF, JPG 같은 파일 형식이 있는가.
- 처리 인원이 결과물에 없는가.
- 구체적 제약 사항이 8~12문장, 번호 달린 한 줄 한 문장인가.
- 답이 들어가 있지 않은가.
- 시급이 25,000원 가정인가.
- 다시 만들 때 필요한 입력이 있는가.
- 수식이 결과물에 없는가.
