# 가상 문제 데이터 합성

선정된 가상 문제 상황 명세서(마크다운 파일)를 입력받아, 학습자가 현장의 업무 프로세스와 병목을 직접 체감하고 실습할 수 있도록 **실무 합성 데이터셋**과 **현재 업무 수작업 재현 스크립트**를 구축합니다.

## 핵심 원칙
- **현재 업무의 충실한 재현**: 자동화 코드, LLM 호출, 머신러닝 분류 모델 등 해결책은 일체 포함하지 않습니다. 현재 담당자가 겪고 있는 수작업 대조와 재작업 과정을 그대로 시뮬레이션합니다.
- **정답 데이터의 철저한 격리**: 정답 매핑 라벨은 채점용 `hidden/` 디렉토리에만 보관하며, 실습생이 접근하는 `data/` 및 재현 스크립트에는 노출하지 않습니다.
- **재현 가능성**: 난수 시드(seed)를 고정하고 특정 운영체제나 로컬 절대 경로에 종속되지 않는 범용 코드로 작성합니다.

## 입력
- **선정된 상황 마크다운 문서** (직전 스킬의 산출물 파일)

> 지정된 파일이 없거나 핵심 항목(상황 이름, 배경 설명, 제약 사항, 비용 가정, 입력 필드 등)이 누락된 경우 부족한 항목만 묻고 대기합니다. 여러 후보가 한 번에 전달되면 `virtual-problem-situation-select`로 안내하여 먼저 선별하도록 합니다.

## 목표
1. 매일 반복되는 업무 데이터를 사실적으로 합성합니다.
2. 수작업 처리 4단계(읽기 → 나누기 → 찾아보기/대조 → 미완성 초안 작성)가 실행 로그에 명확히 드러나도록 스크립트를 구성합니다.
3. 가정된 재작업 비율에 맞추어 불일치/재작업 케이스를 데이터에 반영합니다.
4. 실행 완료 시 처리 건수, 재작업 건수, 추정 인건비 손실액이 출력되도록 합니다.

## 산출물 디렉토리 구조
한 상황당 독립된 폴더 하나를 생성합니다. 폴더 및 스크립트 이름은 해당 업무 도메인 용어에 맞추어 명명합니다.

```text
<문제상황_폴더>/
  README.md             # 학생용 실습/과제 안내서 (문제 정의 및 실습 목표)
  schema.md             # 데이터 필드 명세 및 현장 담당자가 확인하는 이유
  data/                 # 실습용 원천 데이터 (노이즈 포함, 정답 라벨 없음)
    day_inbox.csv       # 당일 유입 업무 데이터
    lookup.csv          # 대조용 기준 마스터 데이터 (필요 시)
    rework_log.csv      # 오류로 인한 재작업 발생 기록 (필요 시)
  hidden/               # 채점 및 평가용 기준 데이터 (실습생 열람 제한)
    ground_truth.csv    # 정답 매핑 기준표 (재현 스크립트에서 참조 금지)
    cost_assumptions.json # 업무 시간 및 비용 가정 파라미터
  <재현_스크립트>.py     # 수작업 대조/처리 과정을 시뮬레이션하는 Python 스크립트
```

## 데이터 생성 규칙
- **데이터 규모**: 기본 1일 치(하루 건수) 분량의 입력 데이터를 생성합니다. (사용자가 별도 기간을 지정한 경우 `일수 × 하루 건수`)
- **현실적인 노이즈 부여**:
  - `data/`에는 오탈자, 유사 명칭, 서식 불일치, 누락 등 실제 현장에서 빈번히 발생하는 비정형 노이즈를 재작업 비율에 맞추어 반영합니다.
  - 단, 파일 손상, 인코딩 오류, 특정 OS 종속 폰트 부재 등으로 파일이 열리지 않거나 스크립트 실행 자체가 실패하는 기술적 결함은 방지해야 합니다.
- **필드 일관성**: 상황 명세서의 '필요한 입력' 항목을 엄격히 준수합니다. 임의의 필드를 추가하지 않으며, 재현에 반드시 필요한 보조 필드만 최소한으로 추가하고 `schema.md`에 사유를 명시합니다.
- **보안 및 프라이버시**: 실존 기업, 실존 인물명, 실제 내부 기밀 정보는 일체 사용하지 않으며 그럴듯한 가상 고유명사를 생성합니다.
- **비정형 파일 재현 (PDF, JPG, 엑셀)**:
  - 명세서에 첨부 파일 형식이 지정된 경우 실제 해당 파일들을 함께 생성합니다.
  - 스캔 문서나 사진(JPG)의 경우 실제 서류처럼 일부 파일에 회전(90°/180°/270°)이나 자연스러운 음영/주름 효과를 부여할 수 있으나, 본문 텍스트를 판독할 수 없게 가리는 인위적인 훼손은 배제합니다.
  - 회전 각도나 정답 텍스트는 `hidden/ground_truth.csv`에만 기록합니다.

## 재현 스크립트 규칙
- **개발 언어**: Python 3
- **외부 패키지**: 효율적인 파일 처리 및 품질 향상을 위해 필요한 경우 범용 라이브러리(pandas, reportlab, Pillow 등)를 적극 활용하며, 필요한 의존성은 `README.md`에 명시합니다.
- **처리 구간 로그 출력**: 매 건을 처리할 때 터미널 로그에 아래 4개 수작업 단계가 나타나야 합니다.
  1. `[읽기]`: 원문 문서에서 어떤 항목을 확인하는지
  2. `[나누기]`: 어떤 필드 단위로 분리하는지
  3. `[찾아보기]`: 어떤 마스터 표나 기준 파일과 대조하는지
  4. `[초안]`: 수작업으로 작성하는 불완전한 결과물 또는 누락 항목
- **정답 참조 금지**: 스크립트 실행 중 `hidden/` 디렉토리 내의 파일은 일체 참조하지 않습니다.
- **실행 결과 요약**: 스크립트 종료 시 총 처리 건수, 재작업 건수, 가정치에 따른 소요 시간 및 비용 손실액 추정치를 깔끔하게 출력합니다.

## 문서 작성 가이드
- **README.md (학생용 실습 가이드)**:
  - 업무 배경 및 문제 상황 요약 (답안 미포함)
  - 스크립트 실행 방법 및 필요한 패키지 설치 안내
  - 폴더 구조 설명 (`hidden/`은 평가용이므로 열람하지 않도록 안내)
  - 실습 과제 목표 (예: "수작업 대조 프로세스를 자동화하여 재작업률을 낮추고 비용을 절감하라")
- **schema.md**:
  - 각 필드명, 데이터 타입, 예시 값, 현장 실무자가 이 항목을 확인해야 하는 이유 서술

## 자기 점검 (Checklist)
산출물 생성 후 다음 항목을 검증합니다.
- [ ] 재현 스크립트가 `hidden/` 디렉토리를 참조하지 않고 독립적으로 실행되는가?
- [ ] 스크립트 실행 시 읽기/나누기/찾아보기/초안 단계가 로그로 가시화되는가?
- [ ] 생성된 데이터 건수와 재작업률이 명세서의 비용 가정과 일치하는가?
- [ ] 정답 라벨이 `data/`에 노출되지 않고 `hidden/ground_truth.csv`에만 격리되었는가?
- [ ] 생성된 파일들이 특정 OS에 종속되지 않고 정상적으로 열리는가?
- [ ] 해결 방안(자동화 알고리즘, LLM 프롬프트 등)이 스크립트나 가이드에 포함되지 않았는가?
